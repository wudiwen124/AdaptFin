## 0. 项目目标与定位

- 目标：做一个 **中文对话式投顾助手**，作为找实习/找工作的作品集项目。
- 用户原始设想：研究分析 / 风险测评 / 行情查询三个 Agent + Function Calling 接 akshare/tushare + LangGraph 编排 + Memory。
- 我做的关键定位修正：项目 = **求职作品**，因此同时要求“能讲深、能演示、两周内可落地”；产品合规上定位为“研究辅助 / 教育模拟”，不接入实盘、不输出指令性买卖建议。

## 2. 竞品调研（为什么最终架构长这样）

### 执行内容

- 通过 GitHub API 拉取 10 个仓库的 star/fork/语言/最近推送，精读 README 与架构章节、源码目录树：
  TradingAgents（102.8k）、OpenBB（72.7k）、ai-hedge-fund（63.3k）、Qbot（18.5k）、FinRobot（7.9k）、wyh22/multi-agent-trading、TrueWealth-AI、TradingAgents-CN 系、jiangge89/trading-agent、rahul-jajala。
- 产出 8 条跨项目工程共识（详见架构终稿 §2），并据此把“3 个 Agent”扩展为 **5 个角色**：Market / Research（内部三分析师并行）/ Risk / Advisor / Auditor+Compliance 闸门。

### 为什么这样设计

- 竞品共同证明：**确定性计算与 LLM 叙事分离**（指标/评分/风控规则交给 Python）、**路由与执行分离**、**独立审计**、**规则化合规**、**数据层抽象+缓存降级**、**模型分档**、**记忆分层**、**评测与收益分离**。
- 对话型竞品（TrueWealth 等）缺 A 股数据与画像记忆；研究型竞品（TradingAgents 等）角色过多不适合对话——所以本项目卡在“对话投顾 + 画像 + 证据审计”的差异点上。

## 4. P2：LangGraph 编排跑通真实链路

### 执行内容

- 模型网关：OpenAI 兼容 + router/deep 分档；
- 两段路由：规则预筛（0 LLM）→ 便宜模型 JSON 结构化兜底；
- 主图：Supervisor → Market / Research（Send 多标的 fan-out + 每标的 3 分析师并行）/ Risk（问卷多轮）/ chat → Advisor → Auditor → Memory Writer；
- 通用 Agent 工具循环（bounded ReAct，工具失败作为观察返回）；
- 风险问卷：答题轮零 LLM（规则编号命中），评分永远走规则；
- 对话 CLI：`scripts/chat_cli.py`。

### 遇到的问题与解决（按时间顺序）

#### 4.1 langchain-core 1.6 的 HumanMessage 没有 `.role`

- 现象：Supervisor 拿到的 user text 一直是空字符串，路由全部落到 chat。
- 排查：在节点里打印消息对象，发现 `type=HumanMessage role=None content=...`。
- 解决：新增 `graph/nodes/text.py`，用 `message_role/content` 兼容 `type`（human→user）与 dict 两种形态，所有节点统一改用它。
- 原因：依赖库 API 演进；只在一个地方做兼容，避免每个节点各写一套。

#### 4.2 LangGraph 1.x 的 Send API 变了

- 现象：`return [Send(...)]` 抛 `InvalidUpdateError: Expected dict`。
- 排查：读本地 langgraph 1.2.11 的 `Command` 签名，发现动态分支要包成 `Command(goto=[Send(...)])`。
- 解决：`send_research` 改为返回 `Command(goto=[...])`。
- 原因：1.x 把“图更新”和“动态控制流”统一到 Command；旧教程的裸 Send 写法已失效。

#### 4.3 每轮传完整 initial_state，把问卷进度重置了

- 现象：风险测评连续答 10 题后 `risk_done` 仍为 False。
- 排查：LangGraph checkpoint 恢复后，本轮输入里的 `q_index=0 / q_scores=[]` 会把已保存的进度覆盖掉。
- 解决：后续轮次只提交 `{"user_id": ..., "messages": [HumanMessage(...)]}`，让非 reducer 通道保留 checkpoint 值；只在首轮提交完整 state。
- 原因：checkpoint 恢复 + 输入合并的语义是“增量更新”，不是每次重放全量。

#### 4.4 GLM-4.7-Flash 额度耗尽（错误码 1305）

- 现象：真实联调一直 429，响应体 `{"error":{"code":"1305"}}`（当日免费额度耗尽）。
- 排查：用同一 key 试 `glm-4-flash / glm-4-air / glm-4-plus / glm-4.5`，全部 200。
- 解决：`.env` 里临时切 router=`glm-4-flash`、deep=`glm-4.5`（均可随时改回）；key 只放本地 gitignore 的 `.env`，不进代码/文档。
- 后续加固：网关识别 1305 自动换备用模型，不空等。

#### 4.5 路由 LLM 把 JSON 模板原样回显

- 现象：报错 `ValueError: 模型未返回合法 JSON: '...confidence: 0.0到1.0...'`。
- 根因一：答题轮文本“1”无规则关键词 → 走了 LLM 路由；模型偶发复述系统提示里的模板。
- 根因二：Supervisor 在 `route_request` **之后**才覆盖问卷意图，顺序反了。
- 解决：
  1. 问卷进行中（`q_index>0` 且未完成）**先于路由**直接锁定 risk 意图——答题轮零 LLM 调用，并新增测试断言 `gateway.calls == []`；
  2. 解析器兼容 ```json / 单反引号包裹；
  3. `llm_route` 解析失败兜底为低置信度 chat，不再抛异常；
  4. 风险选项 LLM 映射失败 → 原题重问。

#### 4.6 httpx.ReadTimeout（测评后研究阶段偶发）

- 现象：测评完成后追问个股研究，报 `ReadTimeout`（原读超时 45s，无重试）。
- 解决：
  - 网关读超时 45s→120s；超时/连接错误指数退避重试；429 重试；1305 换备用模型；
  - 研究三个分析师互相隔离：单个失败只降级该维度，不让整轮崩；
  - Market Agent、CLI 同样兜底（失败提示“请重试”而非堆栈）。
- 原因：真实 LLM 接口慢是常态，韧性必须做在“网关 + 并行边界”，而不是祈祷网络不抖。

#### 4.7 checkpoint msgpack 自定义类型告警

- 现象：`Deserializing unregistered type advisor.schemas.risk.RiskProfile ...`。
- 排查：读 `langgraph/checkpoint/serde/jsonplus.py`，发现宽松模式下 `with_msgpack_allowlist` 因为 base=True 直接返回自身、白名单根本没生效。
- 解决：构造 `JsonPlusSerializer(allowed_msgpack_modules=[...])` 时直接传显式白名单（RiskProfile/RiskLevel/Constraints/Holding/UserProfile/ResearchReport/EvidenceRecord 等），再交给 `MemorySaver(serde=...)`。
- 原因：显式白名单既消除告警，也兼容未来 LangGraph 收紧为严格模式。

#### 4.8 风险测评做完不能重做

- 用户提问：测评后不能修改，想重做怎么办？
- 设计语义：查询只读 / 重做开新问卷（完成前旧等级有效）/ 中途取消保留原等级 / 历史可审计。
- 实现：
  - `risk_dirty` 标记：只有本轮真的产生新测评结果才写库，查询画像不会重复落历史；
  - Supervisor 在问卷进行中（含重做）清空 state 里的旧画像，避免顶掉问卷流程；
  - Store 新增 `risk_history` 表；完成时“原子替换”当前等级并追加历史；
- 新增 4 个场景测试（查询只读、C1→C5 且历史两条、取消保留 C1、取消后路由恢复）。

## 5. P3-A：Auditor 证据级审计

### 执行内容

- 新增 `EvidenceRecord`（tool/args/output/source/data_as_of），`run_tool_agent` 每次工具调用都记录原始证据；
- Market/Research 节点把证据写进 state 的 `tool_observations`（带 reducer，支持并行 fan-in）；
- Advisor 的【证据区】加入“工具原始输出”，回修轮也能看到证据；
- Auditor 升级为确定性检查：
  1. 免责声明；
  2. 指令性买卖表述；
  3. **最终回答里的每个小数必须在工具证据/画像/原话中出现**（拦截编造数字，如编一个不在证据里的 PE）；
  4. **回答中的日期不能超出证据日期集合**（PIT 守卫雏形）；
  - 有问题 → 带具体缺口的 SystemMessage 回修，最多 N 轮。

### 遇到的问题

- “建议立即买入”这种表述没被正则命中（建议和买入之间隔着副词）→ 正则放宽为“指令词 + 0~6 个任意字符 + 动作词”。
- 数字误报控制：只检查带小数点数字（如 42.37、33.89），年份/整数/题目编号不参与；风险画像、用户原话、工具输出都算“允许来源”。

### 为什么

- 防幻觉不能只靠提示词；**数字必须有出处**是可以用测试证明的工程特性，也是面试“怎么防幻觉”的标准答案。

## 6. P3-B：持仓/偏好自动记忆

### 执行内容

- `graph/nodes/extract.py`：规则抽取器
  - 持仓：`买了/加仓/建仓/持有 + 数量? + 代码`、`代码 + 数量 + 股/份/手`；
  - 卖出：`卖出/清仓/减仓/卖掉 + 代码` → 移除；
  - 偏好：`不喜欢/厌恶/偏好/关注/看好 + 目标` → 写入 facts（去重）。
- Memory Writer 每轮对用户原话执行抽取；`Holding.qty` 改为允许未知（只说“买了510300”也能记）；
- 下一轮“分析我的持仓”直接从 Store 读持仓，无需用户重述。

### 为什么先做规则版

- 高频句式规则可单测、零成本、不产生脏数据；“任意表达 LLM 抽取”写进 P4 扩展，且必须加低置信度丢弃。

### 遇到的问题

- `加仓了` 没匹配（正则没允许“了”）→ 动词组统一加 `(?:了)?`；
- 首轮“我买了510300”因带代码被路由成 portfolio 并立刻研究了一次，第二轮又研究 → research_results 累加为 2。测试改用新线程验证第二轮，避免把“跨轮状态保留”当成 bug。

## 9. P5：让“记忆真正可用 + 回答不再空泛”

### 9.1 P5-A 记忆读侧与持久化

背景：用户实测反馈“记忆弱、回答弱”。诊断结论：偏好/事实只写不读、会话历史只存不用、研究结果跨轮累加、MemorySaver 重启即失。

执行内容：

- **读侧补齐**：Supervisor 每轮从 SQLite 组装 `user_memory`（facts/prefs/holdings 摘要）写入 state；Advisor prompt 新增【用户记忆】块。此前 `facts` 只有写入方、没有任何节点读取。
- **会话持久化**：默认 checkpointer 从 MemorySaver 换成 SqliteSaver（`data/checkpoints.db`，带 msgpack 显式白名单）；服务/CLI/UI 按用户隔离 thread。
- **turn 级清理**：`research_results / tool_observations / sources` 改用自定义归约器 + `_TURN_RESET_` 哨兵，Supervisor 每轮清空，解决跨轮证据累加。

遇到的问题与解决：

| 问题 | 解决 | 原因 |
|---|---|---|
| SqliteSaver 连接报 “SQLite objects created in a thread…” | `sqlite3.connect(check_same_thread=False)` | 图的多线程执行器会在不同线程写 checkpoint，官方实现自带锁，允许跨线程 |
| `_Reset` 对象无法被 msgpack 序列化 | 哨兵换成字符串 `_TURN_RESET_`，归约器按值过滤 | 中间写也会进 checkpoint，必须可序列化 |

### 9.2 P5-B 名称解析、反问澄清与多轮上下文

- `orchestration/resolver.py`：本地名称→代码索引（茅台→600519 等），Supervisor 在 quote/research 且无代码时补全；
- `query_gap`：仍无标的或 portfolio 无持仓时，Advisor 收到“请反问澄清”指令，不再硬答编造；
- Advisor 注入【最近对话】（最近 6 条），支持“那 510300 呢”这类省略主语追问；
- 真实名称提问“贵州茅台现在怎么样”现在会走 research 而不是空转。

## 10. P6：多轮指代消解 + 全量真实评测

背景：用户实测“它指代上文”仍失败。诊断根因：**指代消解发生在路由/取数之后**——模型知道“它=600519”时，Market/Research 已经带着空标的跑完了；且只有裸消息、没有线程级实体注册表。

### 10.1 P6-A 实体注册表 + 指代消解

- `orchestration/entities.py`：

- 回答链路前置了真实工具调用（FakeGateway 现在模拟“先 tool_call 后总结”），多轮测试能断言 `tool_observations` 非空。

## 16. 关键技术决策回顾（“为什么这么做”速查）

1. **Agent 按“职责域 + 权限”拆分，而不是按角色数量堆**：取数 Agent 无评价权、测评 Agent 无行情工具，从结构上减少越权/幻觉。
2. **确定性计算优先于 LLM**：指标、问卷评分、风控上限、审计数字核对全部 Python 规则；LLM 只做语义/叙事。
3. **demo 数据源是必做项**：保证无网/接口挂时面试演示 100% 可用，且能标 degraded 演示降级语义。
4. **模型分档 + 网关韧性**：路由用便宜模型、研究用强模型；超时重试、配额换模型、备用链。
5. **记忆分两层 + 脏标记**：checkpoint 管对话，Store 管画像；`risk_dirty` 避免“查询”被当成“变更”写库。
6. **风险测评可重做但原子生效**：旧等级在完成前有效，历史表可审计。
7. **审计闭环优先于花哨功能**：数字出处/PIT 是投顾产品可信度的底线。
