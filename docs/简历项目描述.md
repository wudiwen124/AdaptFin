# AdaptFin 简历项目描述

这份文档整理项目事实和可用于简历的表述。所有数字来自仓库中的测试和评测结果，投递前仍应根据岗位调整关键词。

## 项目概述

AdaptFin 是一个面向 A 股的中文投资研究助手。用户完成风险测评后，可以查询行情、分析个股和持仓，后续对话会继续使用已保存的风险等级、偏好和持仓。系统使用 LangGraph 编排多个执行角色，通过工具调用获取真实数据，并在输出前进行规则审计。

默认数据源为离线 demo，真实行情使用 akshare/baostock/tushare 适配器。项目不接实盘交易，输出定位为研究辅助。

## 实现流程

### 需求与范围

先确定项目只做 A 股研究辅助。实盘交易、收益承诺和复杂回测不进入第一版，因为它们涉及账户权限、合规和额外数据成本。核心场景确定为“风险测评 -> 查行情或研究 -> 结合画像回答 -> 保存后续记忆”。

### 数据与领域模型

使用 Pydantic 定义证券、行情、财务、研究报告、用户和风险画像。数据源统一通过 `DataSourceRouter` 访问，真实接口与 demo 数据具有相同返回结构。MA、RSI、波动率和回撤由本地代码计算。

### LangGraph 编排

Supervisor 使用规则加小模型完成路由，只把请求交给必要的分支。Research 通过 `Send` 并行处理多只股票，每只股票内部再并行运行三个研究角色。Advisor 生成回答后进入 Auditor，发现问题时有限次数回修。

### 记忆

长期资料存储在 `advisor.db`，包括风险等级、持仓、偏好事实和测评历史；会话状态由 SqliteSaver 保存在 `checkpoints.db`。实体注册表保存当前线程提到的证券，用于处理“它现在多少钱”这类追问。偏好召回使用向量相似度，接口不可用时退回关键词匹配。

### 服务与展示

FastAPI 提供聊天、画像、审计和健康检查接口，聊天接口使用 SSE 返回状态与内容。Streamlit 页面负责本地演示，包含风险问卷、用户切换、持仓和对话。

## 可以重点说明的设计

### 为什么拆分多个角色

每个角色只保留与职责相关的工具。Market 不能给投资评价，Risk 不持有行情工具，Advisor 不直接查询原始数据，Auditor 不负责生成第一版回答。这样可以限制单个节点的权限，也方便单独测试。

### 为什么把数值计算放在模型外

指标、评分、仓位限制和日期判断都有明确规则。用 Python 实现后可以直接断言边界，不会因为模型换一种说法就得到不同分数。

### 为什么需要时点校验

财务报告和公告的发布时间与研究截止日不完全相同。如果研究历史日期时使用后来发布的数据，会产生前视偏差。项目把 `as_of` 放进行情请求，并在审计阶段检查公告发布日期和财务报告期。

### 为什么评测三种架构

多个 Agent 会增加调用次数，不能默认认为它一定优于单 Agent。项目比较单 Agent、固定流水线和动态 Supervisor，分别记录完成率、免责声明、内容依据和调用成本，用现有用例判断拆分是否有效。

## 评测结果

真实模型全量评测使用 9 条固定用例：

| 架构 | 完成 | 免责声明 | 内容有据 | 平均 LLM 调用 |
|---|---:|---:|---:|---:|
| 单 Agent | 9/9 | 4/9 | 1/9 | 1.67 |
| 固定流水线 | 9/9 | 8/9 | 5/9 | 3.78 |
| Supervisor 编排 | 9/9 | 9/9 | 9/9 | 3.00 |

结果只能说明这 9 条用例上的表现。样本量较小，也不能用股票涨跌衡量工程质量。

## 常见问题

**为什么使用 LangGraph，而不是一个 while 循环？**

本项目需要条件分支、并行任务、持久化状态和有限轮审计。LangGraph 把这些关系写成显式图，节点状态和失败位置更容易检查。

**怎样减少模型编造数据？**

数据由工具返回并保存为证据；指标和评分由代码计算；Advisor 只能基于证据生成分析；Auditor 核对数字和日期。这个流程能发现一部分问题，但不能保证所有自然语言推断正确。

**长期记忆和会话记忆有什么区别？**

长期记忆保存用户画像、持仓和偏好，跨会话仍然存在。会话记忆保存当前对话的消息和中间状态，用于继续上一轮问题。两者用途不同，因此分别存储。

**项目是否提供真实投资建议？**

不提供。项目定位是研究辅助和教育演示，不接交易接口，不保证收益，回答中会保留风险提示。

## 投递时的表述边界

- 默认数据源是 demo，不能写“全市场实时数据”。
- 向量召回依赖外部 embedding 服务，接口不可用时使用关键词 fallback。
- 105 个测试是离线统计，不代表 105 个真实模型场景全部通过。
- 9 条评测用例的结果不能外推为一般模型能力。
- 项目没有登录、权限和多租户能力，不能描述成生产级投顾系统。
